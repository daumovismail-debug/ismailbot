# 🎛️ ПРОТОКОЛ ПРОДАКШЕНА (оркестрация команды) — как агенты безопасно связаны

> Единый «договор» конвейера. Решает 10 рисков связки: строгие схемы, ключ-кадр,
> гейты качества, чекпоинты, арбитр, тайминги. Это ТЗ для подключения (Этап B).

## 1 источник истины
- **Паспорт проекта** (`project-bible.md`: стиль, палитра, свет=эмоция, язык, каста)
  + **бриф Режиссёра** = истина. При конфликте приоритет: **Паспорт > Режиссёр >
  агент**. Никто не переопределяет облик/тон в обход Паспорта.

## Единый объект серии (его обогащает каждый этап)
Через конвейер идёт ОДИН JSON-объект, кадры — по жёсткому ключу `id`:
```json
{
  "episode_id":"ep_001","project":"Люстра или развод",
  "brief": {"tone":"...","hook_type":"...","target_emotion":"..."},
  "cast": {"heroine":{...},"husband":{...}},
  "music_mood":"tense single track",
  "shots":[
    {"id":1,"act":"COLD OPEN","t":"0-3",
     "characters":["heroine"],            // Сценарист
     "voice_kz":"...","voice_ru":"...","emotion":"angry",
     "image_prompt":"...","references":["heroine"],  // Художник
     "camera":"push-in","motion":"...","duration":3,"continuity":"...", // Аниматор
     "voice_id":"VOICE_HEROINE","audio_dur":2.6,"lipsync":true,         // Голос
     "image_path":null,"video_path":null,"audio_path":null,            // артефакты
     "status":"pending","qc":{} }
  ],
  "edl": {}                                // Монтажёр
}
```

## Контракт этапа (для КАЖДОГО агента)
1. **Читает** только разрешённые поля (вход) из объекта.
2. **Пишет** только свои поля (выход) — не трогает чужие.
3. Перед передачей — **валидация схемы** (поля/типы на месте) → иначе стоп с понятной ошибкой.

---

# 🛡️ Как лечим 10 рисков

**1. Несовпадение форматов** → строгая **JSON-схема** + валидатор на КАЖДОМ стыке;
не прошло — не передаём дальше, чиним сразу (а не падаем в середине).

**2. Рассинхрон кадров** → `id` кадра — **жёсткий ключ**; после каждого этапа
проверка: число кадров и их id **совпадают** с исходными (иначе стоп).

**3. «Испорченный телефон»** → **гейт качества после Сценариста** (Режиссёр+Контролёр
принимают сценарий ДО рисования). Слабую основу не пускаем вниз — дешевле починить рано.

**4. Несовпадение id персонажа/голоса** → `character_id`/`voice_id` берутся ТОЛЬКО
из касты; валидатор проверяет, что каждый упомянутый id **существует** в касте.

**5. Каскад тайминга** → **озвучка — источник истины по времени**: `duration` кадра
= `max(мин_кадр, audio_dur)`. Не влезает → флаг `split` (дробим кадр). Монтажёр
строит таймлайн строго по этим длительностям.

**6. Контролёр: тупик/пропуск** → severity: **block** (стоп, переделка) / **warn**
(в лог). **Лимит 3 попытки** на кадр → потом эскалация пользователю. Чёткие пороги
(face_match≥0.6 и т.д.), чтобы не «на глаз».

**7. Падение движка в середине** → **чекпоинты**: каждый готовый артефакт (картинка/
клип/аудио) сохраняется на диск; повтор — **только упавшего кадра**, остальное не
теряется. Идемпотентность: повтор шага не ломает уже сделанное.

**8. Конфликт решений** → **арбитр = Режиссёр**, приоритет Паспорта (см. «истина»).
Решение арбитра пишется в объект, агенты ему следуют.

**9. Долго/дорого** → тайм-аут на вызов; **параллелим независимые кадры**; кэш
эталонов героя/касты (не генерим заново); бюджет-лимит на серию; «мягкая деградация»
(если кадр не вышел за лимит — плейсхолдер/Ken Burns, серия не встаёт целиком).

**10. Потеря состояния** → **машина состояний серии** на диске: статус каждого кадра
(`pending/done/failed`) сохраняется после каждого шага. Перезапуск сервера →
**продолжаем с последнего хорошего кадра**, а не с нуля.

## Машина состояний кадра
`pending → in_progress → done` либо `failed → retry(≤3) → escalate`.
Серия `done`, когда все кадры `done` и финал прошёл Контролёра.

## Резюме
Связка становится «как у профи»: строгие схемы, кадр-ключ, ранние гейты качества,
проверка id, тайминг от озвучки, лимиты переделок, чекпоинты, арбитр, параллель и
сохранение состояния. Это план реализации на Этапе B.
